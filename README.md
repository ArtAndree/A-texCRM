# CRM

Учебная frontend-CRM на React, Vite и React Router, без backend. Эта папка — единственная основная версия: локальный запуск и публикация на GitHub Pages используют одни исходники.

## Запуск

Требуется Node.js 22.12+.

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте адрес из терминала. Терминал должен оставаться открытым, пока работает локальный сайт. В PowerShell используйте `npm.cmd`, если выполнение `npm.ps1` запрещено. Для установки строго по lock-файлу можно использовать `npm.cmd ci`.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
npm.cmd run package
```

Последняя команда создаёт `release/crm-github-ready.zip` из текущих исходников. В архив входят код, тесты, настройки, инструкция и `.github/workflows/deploy.yml`. Зависимости, собранный сайт, старые версии и служебные материалы в архив не входят. Перед передачей архива выполните тесты и сборку.

Если в ограниченной среде загрузчик конфигурации Vite выдаёт Access denied, добавьте к команде запуска или сборки `-- --configLoader native`.

## GitHub Pages

1. Распакуйте `release/crm-github-ready.zip` и загрузите его содержимое в корень репозитория: `package.json`, `src`, `.github` и остальные файлы должны лежать прямо в корне, без дополнительной папки. Сам ZIP загружать не нужно.
2. При обновлении прежней версии также удалите из репозитория устаревшие `src/design.css` и `src/components/layout/Header.jsx`, если они там есть. Загрузка новых файлов через сайт GitHub сама старые файлы не удаляет.
3. В Settings → Pages выберите Source → GitHub Actions.
4. Сохраните изменения в ветку `main`. Готовый workflow выполнит тесты, сборку и публикацию. Для другой основной ветки измените `branches` в `.github/workflows/deploy.yml`.
5. Дождитесь успешного выполнения во вкладке Actions. Адрес сайта появится в Settings → Pages.

При локальной разработке используются обычные адреса `/clients`. Production-сборка автоматически использует HashRouter: `/#/clients`. Благодаря этому переходы и обновление страниц работают на GitHub Pages без серверной настройки. Ресурсы имеют относительные пути (`base: './'`). Отдельно менять исходники перед публикацией не требуется.

## Демо-вход и данные

Любые непустые логин и пароль открывают приложение. Введённое имя отображается в приветствии, меню и Dashboard и хранится вместе с маркером сеанса в sessionStorage. После выхода они удаляются. Пароль не сохраняется и не отправляется.

По согласованному поведению данные, авторство действий и «Мой план на месяц» относятся к демо-менеджеру Анне Смирновой (`m1`). Введённое имя меняет только отображаемую подпись. План учитывает сумму её сделок, переведённых в «Успешно» в текущем календарном месяце. При повторном открытии сделки она исключается из результата; план — 3 000 000 ₽.

Восстановление пароля — демонстрация двух форм: код из 4–6 цифр и новый пароль с повтором. Письма не отправляются, пароль не изменяется.

CRMContext хранит клиентов, сделки, комментарии и историю в localStorage. Изменения сохраняются после обновления страницы. Данные localhost и опубликованного сайта раздельные; синхронизации между пользователями нет. Сброс демо-данных доступен внизу страницы после подтверждения. Ключи и формат существующего хранилища сохранены.

## Возможности

- Dashboard: показатели, списки новых лидов и активных сделок, фильтр внимания, этапы, личный план, события и история.
- Kanban: восемь этапов, фильтр менеджера, создание сделки, перенос карточек мышью, независимая вертикальная прокрутка этапов колесом и горизонтальное перетаскивание доски за заголовки или свободное место. Этап также можно поменять в карточке сделки. Выбранный менеджер сохраняется в сеансе при возврате из карточки.
- Клиенты: поиск, фильтры источника и менеджера, единый прокручиваемый список с закреплёнными заголовками, создание и карточка клиента.
- Формы: создание клиента внутри сделки, выпадающие списки с управлением клавиатурой, закрытие через отмену, Escape или фон. Источники видны целиком; в форме клиента менеджеры прокручиваются только при более чем пяти вариантах.
- Сделка: изменение названия, суммы, этапа, менеджера, статуса и даты окончания с сохранением; постановка и завершение задачи, комментарии, история изменений.
- Карточка клиента: контакты, сделки, комментарии, история, демонстрационный документ и диаграмма результатов.

## Структура

```text
src/
  assets/        Волнистые SVG-фоны
  components/    Общие элементы, формы, карточки и layout
  context/       Демо-сеанс и общее состояние CRM
  data/          Mock-данные и справочники
  pages/         Экраны приложения
  utils/         Изменения данных, валидация, расчёты и хранилище
  App.jsx        Маршруты и проверка демо-сеанса
  main.jsx       Запуск приложения, выбор роутера
  styles.css     Единый файл оформления и адаптивных правил
tests/           Тесты данных и бизнес-логики
scripts/         Сборка архива исходников
.github/         Автоматическая публикация GitHub Pages
```

Используется Manrope 400/500/600/700 через Google Fonts; без интернета доступен системный запасной шрифт. Дизайн воссоздан по предоставленным скриншотам: заголовки 24px/500, секции 18px/500, метрики 32px/700, основной текст 15px, подписи 13px. Правки интерфейса вносятся в `src/styles.css`. Сжатый код собранной страницы не предназначен для ручного редактирования.
